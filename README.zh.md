# Signal RSS

[English](README.md) · **简体中文**

订阅 RSS / Atom / RSS 1.0（RDF）订阅源，在 Obsidian 里用独立的阅读标签页阅读，并把任意文章保存成 vault 里的 Markdown 笔记。

## 功能

- **订阅管理** —— 粘贴订阅源地址，或者直接粘贴网站主页都能添加；支持 RSS 2.0、Atom 和 RSS 1.0（RDF）。订阅源可以归入分组，分组本身也能在订阅树里新建、重命名和删除。
- **右侧边栏的订阅列表** —— 搜索框、过滤器、订阅树、文章列表，以及它们之间的拖拽分隔线，全部住在右侧边栏。挑选文章的地方只有这一个，列表选中什么，阅读区就显示什么。
- **阅读标签页** —— 选中的文章在主区域自己的标签页里打开。标题会写进标签名和视图头部；正文上方是一行操作按钮：加星标、标记已读／未读、抓取全文、在浏览器打开、存为笔记。
- **全文抓取** —— 订阅源只给摘要时，会去抓原文页面并提取正文，读到的和存下的都是完整内容。
- **Markdown 导出** —— 把任意文章存成笔记。目标文件夹、文件名、frontmatter 模板和正文模板都可以自己配。
- **自动刷新** —— 按你设定的间隔在后台拉取订阅源。设为 0 就关掉自动刷新。Ribbon 图标的提示里会带上当前未读数。
- **已读状态** —— 每个订阅源、每个分组的未读数，全局未读数，已读／未读切换，以及星标列表。
- **搜索** —— 边打字边筛文章列表，匹配标题、作者和摘要。
- **OPML** —— 导入其他阅读器导出的 OPML 文件，也能把自己的订阅导出成 OPML。
- **界面语言** —— 英语和简体中文，跟随 Obsidian 的语言设置。

## 安装

### 从社区插件市场安装

在 **设置 → 第三方插件 → 浏览** 里搜索 "Signal RSS"。

### 手动安装

1. 从最新的 Release 下载 `main.js`、`manifest.json` 和 `styles.css`。
2. 把它们放进 `<你的 vault>/.obsidian/plugins/signal-rss/`。
3. 重载 Obsidian，在 **设置 → 第三方插件** 里启用插件。

## 使用

1. 点 Ribbon 上的 RSS 图标，订阅列表会在右侧边栏打开。
2. 添加订阅源。列表为空时有「添加订阅源」按钮；命令面板里的「Signal RSS: 添加订阅源」在任何地方都能用；已经分好组之后，右键分组标题会看到「新增订阅源…」，并自动填好该分组。粘贴网站主页也可以 —— 插件会自己在页面上找订阅源链接。
3. 文章出现在列表顶部的三个过滤器下面。点一篇，它会在主区域的阅读标签页里打开。
4. 在阅读区点「存为笔记」，把文章写进 vault。

在侧边栏右键某个订阅源，可以刷新、标为已读、编辑和删除。分组标题上的菜单还带着 OPML 导入导出、整个分组的全部标为已读／未读，以及分组自己的重命名和删除 —— 删除分组只会把它里面的订阅源放回**未分组**，不会删掉它们；重命名则带着它们一起走。

在订阅树下方的空白处右键，可以新建分组，或者添加一个不归入任何分组的订阅源。新建的空分组会一直留在树里 —— 它不是一片空白，而是显示一行「新增订阅源…」（并预填该分组）—— 直到你把它删掉。

列表只住在侧边栏，所以没有"放哪一栏"可选项：「Signal RSS: 显示或隐藏侧边栏的订阅列表」用来显示和隐藏它；隐藏期间，阅读区的空状态会给出一个按钮把它叫回来。

### 列表面板

- **搜索框** —— 边打字边过滤文章列表，打字停顿一小会儿才重绘，不会和光标打架。
- **三个过滤器** —— **全部文章**、**未读**、**星标**，各自带着数量。在订阅树里点某个订阅源，则把列表收窄到该源。
- **订阅树** —— 分组标题点一下折叠／展开；折叠状态下会显示该分组的未读总数。
- **拖拽分隔线** —— 订阅树和文章列表之间的分隔线可以调整两者高度。拖拽即可，双击恢复默认，聚焦后也能用方向键微调（按住 Shift 步子更大）。

## 命令

| 命令 | 说明 |
| --- | --- |
| 打开 RSS 阅读器 | 显示阅读标签页 —— 没选文章前是空的 |
| 刷新全部订阅 | 拉取所有订阅源 |
| 添加订阅源 | 打开添加订阅源对话框 |
| 导入 OPML 文件 | 从 OPML 文件导入订阅 |
| 导出 OPML 文件 | 把 OPML 文件写到 vault 根目录 |
| 把当前文章保存为笔记 | 保存阅读区里打开的文章 |
| 把全部文章标为已读 | 清掉所有未读状态 |
| 折叠全部分组 | 把订阅树里的分组全部折叠 |
| 展开全部分组 | 把订阅树里的分组全部展开 |
| 显示或隐藏侧边栏的订阅列表 | 显示或隐藏右侧边栏的列表 |

后三个需要"有东西可操作"的命令 —— 保存当前文章、折叠全部分组、展开全部分组 —— 在无事可做时会从命令面板里隐藏。

## 设置

设置页分成四个标签页。

### 基础配置

| 设置项 | 说明 |
| --- | --- |
| 自动刷新间隔 | 后台拉取订阅源的间隔（分钟）；0 表示关闭 |
| 请求超时 | 等待订阅源响应的最长时间（5–120 秒） |
| 每个订阅源保留文章数 | 单个订阅源最多保留的文章数，超出后丢弃最旧的 |
| 打开即标记已读 | 打开文章时立即清掉未读标记 |
| 打开时抓取全文 | 订阅源只提供摘要时，去抓原文页面 |
| 刷新时抓取全文 | 改为在刷新时抓取，之后可以离线阅读 |
| 自定义缓存目录 | 存放缓存的 vault 相对目录，旁边有「迁移缓存」按钮 |

### 订阅源

所有订阅源的列表。工具栏上是「新增订阅」「导入 OPML」「导出 OPML」，下面有一个按标题、分组或地址筛选的搜索框；每个订阅源一行，显示标题、分组，以及三个操作：刷新、编辑、删除。

### 笔记导出

| 设置项 | 说明 |
| --- | --- |
| 保存后打开笔记 | 在新标签页里打开刚生成的笔记 |
| 笔记文件夹 | 保存文章的目标文件夹，不存在时自动创建 |
| 文件名模板 | 笔记文件名的模板 |
| frontmatter 模板 | 写在每篇笔记顶部 `---` 之间的元数据 |
| 笔记正文模板 | 包裹文章正文的模板 |

### 关于

显示版本号，一个「检查更新」按钮（在 Obsidian 里打开本插件页面），以及「恢复默认设置」—— 把本页所有选项恢复默认，订阅源列表会保留。

### 模板变量

文件名和两个模板都支持这些变量：

| 变量 | 取值 |
| --- | --- |
| `{{title}}` | 文章标题 |
| `{{feed}}` | 订阅源标题，没有标题时用它的地址 |
| `{{group}}` | 订阅源所属分组 |
| `{{author}}` | 文章作者 |
| `{{link}}` | 文章地址 |
| `{{published}}` | 发布时间，默认格式 `YYYY-MM-DD` |
| `{{created}}` | 笔记生成时间，默认格式 `YYYY-MM-DD` |
| `{{summary}}` | 订阅源提供的摘要 |
| `{{content}}` | 文章正文（已转成 Markdown）—— 只在正文模板里用 |

日期变量在冒号后面可以跟 Moment.js 格式，例如 `{{published:YYYY-MM-DD HH:mm}}`。追加 `:yaml` 会按 YAML 规则转义，默认的 frontmatter 模板就是这么写 `{{title:yaml}}` 和 `{{author:yaml}}` 的。默认文件名模板是 `{{published:YYYY-MM-DD}} {{title}}`，默认笔记文件夹是 `RSS Inbox`。

## 数据放在哪

- 订阅列表、已读／星标状态和设置都存在插件的 `data.json` 里。
- 文章内容缓存在 vault 根目录的 `.signal-rss/` 下，每个订阅源一个 JSON 文件 —— 以点开头，所以不会出现在文件浏览器里，也不进 Obsidian 的索引。这个目录可以改；但改它本身不会搬动任何文件，旁边那个 **迁移缓存** 按钮才是第二步 —— 它会把**上一个**用过的目录里的缓存合并过来，是合并而不是覆盖，所以不会丢已读标记，也不会丢抓好的正文。
- 0.7.0 及更早的版本把缓存放在插件目录里（`<配置目录>/plugins/<插件 id>/cache/`，配置目录通常是 `.obsidian`）。如果你从插件还叫 `rss-subscribe` 的时候就开始用，留在旧插件 id 目录下的缓存需要手动搬进当前目录。
- 除非你明确保存文章，否则不会往你的笔记目录里写任何东西。

## 隐私与网络访问

插件会发网络请求，但只发往你订阅的地址：

- 拉取文章时请求订阅源地址。
- 抓取全文时请求文章自己的地址。

没有账号，没有遥测，没有统计，也不经过任何第三方服务。请求走 Obsidian 的 `requestUrl` API，不会经过我们的代理。

## 订阅源加载不了怎么办

有些地址本身就不可达、被限流，或者服务端挂住不返回。Signal RSS 会在配置的超时时间后放弃并把原因报出来，而不是无限期等待；如果是主机本身不可达，它会提前放弃，而不是把每条猜测路径都重试一遍。

罪魁祸首常常不是你想要的那个网站，而是公共 **RSS 桥**（比如 `rsshub.app` 或某个社区实例）：

- 大多数公共实例限流很严，负载高时直接丢请求。
- 在某些网络或地区可能根本访问不了。
- 在一个本身健康的实例上，单条路由也可能坏掉 —— 实例根路径秒回，而某条特定路由永远不返回，因为实例自己抓上游时挂住了。可以换一个实例试同一条路由，或者[自建实例](https://docs.rsshub.app/deploy/)，后者可靠得多。

订阅之前想确认一个订阅源能不能用，直接在浏览器里打开它的地址：正常的会显示原始 XML，坏掉的会报错、白屏，或者一直转圈。

## 安全说明

订阅源内容属于第三方标记，一律按不可信处理：

- 显示或保存之前，都会被裁剪到一份很小的标签和属性白名单。`on*` 事件、`style`、以及任何 `javascript:` 地址都会被直接丢掉。
- 文章正文用 Obsidian 的 `sanitizeHTMLToDom` 插入；本插件里任何地方都没有用 `innerHTML`。
- 来自订阅源的代码块会用一个比其中最长反引号串更长的分隔符重新围栏，所以订阅源没法把 `dataviewjs` 或 `templater` 围栏夹进笔记里等着以后被执行。
- 文件只会在你的 vault 内创建，而且只在你要求保存笔记时创建。

## 移动端

插件支持移动端（`isDesktopOnly: false`）。它只使用跨平台的 Obsidian API —— 不碰 Node.js 文件系统。

布局是真正为手机做的，而不只是能显示：

- 订阅列表住在右侧边栏，在手机上就是抽屉。点 Ribbon 上的 RSS 图标打开它；选中文章后会把它收起来，文章立刻就能看到。
- 长按订阅源、分组标题，或树下方空白处，会打开对应菜单（刷新、标为已读、编辑、删除、OPML、全部标记、新建分组、重命名、删除分组），因为手机上没法右键。
- 触摸目标、搜索框和阅读区的边距都按拇指操作和 iOS 的最小输入字号设计。

## 开发

需要 Node.js 18 或更高版本（CI 用 22）和 Obsidian 1.7.2 或更高版本。

```bash
npm install
npm run dev     # 监听构建
npm run build   # 类型检查 + 生产构建
```

把 `main.js`、`manifest.json` 和 `styles.css` 拷进测试 vault 的 `.obsidian/plugins/signal-rss/` 即可试跑。

### 目录结构

| 路径 | 内容 |
| --- | --- |
| `src/main.ts` | 插件入口：命令、视图注册、共享列表状态、刷新与订阅源管理 |
| `src/settings.ts` | 分标签页的设置页 |
| `src/i18n/index.ts` | 所有用户可见文案，`en` 与 `zh-cn` 两张表 |
| `src/core/` | 订阅源解析、网络请求、错误归类、全文提取、OPML、HTML 清洗、缓存存储 |
| `src/view/` | 侧边栏列表面板与阅读标签页 |
| `src/note/` | 模板渲染与笔记写入 |
| `src/ui/` | 添加订阅源、分组命名两个对话框 |
| `styles.css` | 插件样式，使用 Obsidian 的 CSS 变量 |

所有用户可见文案都必须走 `t()`，不允许有字面量直接进入界面。

### 检查

发版之前，`manifest.json`、`package.json` 和 `versions.json` 三处的版本号必须一致：

```bash
node .github/scripts/check-version.mjs          # 版本号一致性 + manifest 规则
node .github/scripts/check-version.mjs --tag X  # 同时校验 tag 与 manifest 是否匹配
```

CI 会跑这个脚本，外加类型检查、生产构建，以及一次针对 `main.js` 的扫描 —— 检查有没有 Obsidian 审核拒绝的动态执行 API。

### 发版

发版由 GitHub Actions 驱动，构建产物由 CI 上传（`main.js` 不进仓库）：

| Workflow | 触发条件 | 结果 |
| --- | --- | --- |
| `ci.yml` | 推送到 `main`、任意 PR | 类型检查、构建、安全扫描、产物检查 |
| `version-check.yml` | 推送、打 tag、PR | 版本号与 manifest 一致性 |
| `release.yml` | 推送 tag，或手动触发 | 创建 GitHub Release，附 `main.js`、`manifest.json`、`styles.css` |
| `beta.yml` | `main` 上提交信息首行以 `[beta]` 或 `[rc]` 开头 | 发布 `<version>-beta.N` 预发布，供 [BRAT](https://github.com/TfTHacker/obsidian42-brat) 安装 |

在三个文件里都升好版本号、提交，然后推一个**不带 `v` 前缀**的 tag：

```bash
git tag 0.9.0 && git push origin 0.9.0
```

也可以在 Actions 页面手动跑 **Release** 并填入版本号，workflow 会自己创建 tag。正式发版前想先测，就让 `main` 上的提交信息首行以 `[beta]` 开头（用 `[rc]` 会顺手清掉更早的预发布），然后用 BRAT 安装产生的预发布版本。关键字只在首行最开头才算数 —— 正文里提到它们不会触发预发布。
